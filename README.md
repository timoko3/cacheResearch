# Cache Research

Исследование кэша на C++. Сборка описана в `CMakeLists.txt`, стандартные
конфигурации — в `CMakePresets.json`.

## Требования

- CMake 3.24 или новее.
- Компилятор с поддержкой C++17 и `std::filesystem` (например, GCC 9+,
  современный Clang со стандартной библиотекой C++17 или MSVC из VS 2022).
- Ninja для готовых presets. Вручную можно выбрать другой генератор.
- Заполненный подмодуль `generalFunctions`.

После клонирования инициализируйте подмодуль:

```sh
git submodule update --init --recursive
```

В `.gitmodules` указан SSH-адрес GitHub: для этой команды нужен настроенный
SSH-доступ. CMake сам ничего не скачивает и сообщает, если файлов подмодуля нет.

На Windows для GCC/MinGW добавьте каталог компилятора и Ninja в `PATH`.
Для MSVC запускайте команды из Developer PowerShell for VS, где настроены
компилятор, заголовки и библиотеки. Абсолютные пути к инструментам в проекте
не зафиксированы.

## Настройка, сборка и запуск

Все команды выполняются из корня проекта.

```sh
cmake --preset debug
cmake --build --preset debug --parallel
cmake --build --preset debug --target run
```

Первая команда проверяет компилятор и генерирует правила для Ninja в
`build/debug`. Вторая компилирует `.cpp` в объектные файлы, собирает статическую
библиотеку и линкует приложение. `--parallel` разрешает параллельную сборку.
Третья сначала проверяет актуальность сборки, затем запускает приложение
из каталога с исполняемым файлом и `config.txt`.

**Текущее ограничение:** исходный код кэша пока не собирается. CMake не исправляет
ошибки C++; команды полной сборки и `run` заработают после их устранения.
Список обнаруженных проблем приведён ниже. Файловую библиотеку можно собрать
отдельно уже сейчас:

```sh
cmake --build --preset debug --target general_functions --parallel
```

Для замеров производительности используйте отдельную Release-сборку:

```sh
cmake --preset release
cmake --build --preset release --parallel
cmake --build --preset release --target run
```

Debug предназначен для отладки, Release включает оптимизации компилятора.
Их промежуточные файлы лежат в разных каталогах, поэтому режимы не мешают
друг другу. Исполняемый файл будет в `build/debug/bin/Debug/` либо
`build/release/bin/Release/`; на Windows его имя — `cache_research.exe`,
на Linux — `cache_research`.

`config.txt` копируется рядом с программой при сборке цели приложения.
Редактируйте исходный файл в корне: следующая сборка обновит копию,
даже если C++-файлы не менялись. Сейчас чтение конфигурации в `main.cpp`
закомментировано; копирование лишь готовит файл для будущего использования.
При ручном запуске относительные пути считаются от рабочего каталога процесса,
поэтому удобнее использовать цель `run`.

## Как устроен CMakeLists.txt

1. `cmake_minimum_required` задаёт минимальную версию и правила поведения CMake.
   Версия 3.24 нужна в том числе для свойства `COMPILE_WARNING_AS_ERROR`.
   Проверка каталогов запрещает сборку прямо в исходниках, чтобы не засорять их.
2. `project(CacheResearch LANGUAGES CXX)` объявляет проект и включает только C++.
   CMake обнаруживает компилятор и проверяет, что он может собрать программу.
3. `add_library(general_functions STATIC ...)` описывает файловые функции и
   вспомогательные исходники как отдельную библиотеку. Собственного CMake
   у подмодуля нет, поэтому цель описана в родительском проекте. Пустой пока
   `logger.cpp` также включён для его дальнейшей реализации.
4. `add_executable(cache_research ...)` перечисляет исходники приложения явно.
   При добавлении нового `.cpp` его нужно внести сюда: состав сборки виден
   при просмотре изменений и не зависит от случайных файлов в каталоге.
   Заголовки в списках нужны для удобного отображения в IDE.
5. `target_link_libraries` связывает приложение с библиотекой. CMake сам
   определяет порядок сборки и команду линковки. `CacheResearch::general_functions`
   — имя-псевдоним той же цели, отдельную библиотеку оно не создаёт.
6. `target_compile_features(... cxx_std_17)` требует как минимум C++17:
   он нужен для `std::filesystem` и `std::string_view`. `PUBLIC` у библиотеки
   передаёт это требование и путь к заголовкам её потребителям. `PRIVATE`
   применяет настройку только к указанной цели. `CXX_EXTENSIONS OFF` выбирает
   стандартный режим языка вместо режима с расширениями компилятора.
7. `target_compile_options` включает `/W4` для MSVC и
   `-Wall -Wextra -Wpedantic` для GCC/Clang. Предупреждения помогают замечать
   проблемы, но по умолчанию не превращаются в ошибки. Флаги применяются
   к двум целям проекта, а не меняют глобальные настройки всего дерева сборки.
8. `$<CONFIG>` вычисляется для выбранной конфигурации (например, Debug).
   Это позволяет одинаково раскладывать файлы при использовании Ninja и
   генераторов с несколькими конфигурациями, например Visual Studio.
9. `cache_research_config` обновляет файл конфигурации перед сборкой приложения.
   `copy_if_different` не переписывает одинаковую копию; `VERBATIM` обеспечивает
   правильную передачу аргументов, включая пути с пробелами.

## Дополнительные настройки

Список доступных конфигураций:

```sh
cmake --list-presets
```

Строгая проверка предупреждений включается явно:

```sh
cmake --preset debug -DCACHE_RESEARCH_WARNINGS_AS_ERRORS=ON
```

Чтобы отключить её, повторите команду с `OFF`. Значения `-D` сохраняются
в `CMakeCache.txt` соответствующего каталога сборки между вызовами CMake.

Presets дополнительно создают `compile_commands.json` в каталоге сборки.
Он содержит реальные команды компиляции и помогает clangd и другим
инструментам понимать пути заголовков и параметры языка.

Без presets можно настроить сборку вручную:

```sh
cmake -S . -B build/manual -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build/manual --parallel
```

Для Visual Studio 2022 конфигурация выбирается при сборке:

```sh
cmake -S . -B build/vs -G "Visual Studio 17 2022" -A x64
cmake --build build/vs --config Debug --parallel
cmake --build build/vs --config Debug --target run
```

При смене компилятора или генератора используйте новый каталог сборки.
Машинные настройки можно хранить в `CMakeUserPresets.json`; он и каталоги
сборки исключены из Git. Общие presets остаются в репозитории.

## Что пока мешает собрать приложение

Исходники сохранены без изменений. В текущей реализации обнаружены:

- Определения шаблонного `cache_t::lookupUpdate` находятся в `cache.cpp`
  и не видны в `main.cpp` при инстанцировании. Для такого использования
  реализация должна быть доступна из заголовка, например через `.tpp`.
- `cache_t::full()` объявлен, но не определён.
- `nothing()` не принимает аргументов и возвращает `void`, а реализация кэша
  вызывает загрузчик с ключом и ожидает значение типа `T`.
- `cache_` объявлен как `std::list<T>`, но реализация обращается к элементу
  через `.first` и конструирует его из `(key, page)`. Для `T = int`
  эти операции некорректны; нужно согласовать представление данных.
- Поля вложенного `CacheStats` приватные, хотя внешний класс обращается к ним.
  Счётчики также не инициализированы перед увеличением.
- `constexpr char* CONFIG_FILE_NAME` указывает на строковый литерал:
  нужен указатель на `const char` или массив константных символов.

Отдельная компиляция библиотеки проверяет только `generalFunctions`.
Она не означает, что приложение собрано или что алгоритм кэша корректен.
Автоматические тесты пока не подключены: в проекте их нет.

## Проверка настройки сборки

Проверено на Windows с CMake 3.29.2, Ninja 1.12.0 и GCC/MinGW 13.2.0:

- Presets Debug и Release успешно конфигурируются.
- `general_functions` собирается в обоих режимах; в Release проверена также
  настройка `CACHE_RESEARCH_WARNINGS_AS_ERRORS=ON`.
- Копии `config.txt` в каталогах Debug и Release совпадают с исходным файлом.
- Ninja Multi-Config собирает библиотеку и копирует конфигурацию для Debug
  и Release, в том числе в каталоге сборки с пробелом в пути.
- Полная Debug-сборка компилирует исходники, но завершается ошибкой линковки
  `undefined reference` к `cache_t::lookupUpdate`. GCC также сообщает
  о некорректном преобразовании строкового литерала в `char*` в `main.cpp`.

MSVC и Linux в этой среде не проверялись. Запуск приложения и корректность
алгоритма не проверены, поскольку исполняемый файл пока не линкуется.

Справочник: [CMake Presets](https://cmake.org/cmake/help/v3.24/manual/cmake-presets.7.html),
[требования к стандарту языка](https://cmake.org/cmake/help/v3.24/command/target_compile_features.html).
