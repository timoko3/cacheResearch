# Исследование алгоритмов кеширования

Как вместимость кеша влияет на выбор алгоритма вытеснения? Когда полезно
разделять память на несколько уровней? Исследование сравнивает LRU, LFU,
ARC, 2Q и LIRS на искусственных последовательностях запросов и рассматривает
эти вопросы в трёх моделях с разными условиями доступа к данным.

[Обзор экспериментов](conclusions.md) объединяет основные результаты,
численные примеры и границы выводов.

| [Иерархия, приближённая к процессорной](hierarchy.md) | Как распределение памяти и сочетание алгоритмов влияют на стоимость обращения? | Три уровня, всего 290 страниц; ограниченные размеры и возрастающая стоимость доступа | Средняя стоимость запроса |
| [Иерархия с бесплатным обращением к уровням](unrestricted.md) | Может ли разделение общего объёма уменьшить число загрузок? | От одного до трёх уровней, шесть общих объёмов; свободное разбиение памяти | Загрузки из источника на 1000 запросов |

В процессорной модели вместимости ограничены значениями L1 ≤ 4, L2 ≤ 64
и L3 ≤ 256 страниц. Стоимости обращений к уровням равны 1, 3 и 10 условным
единицам, загрузки из внешней памяти — 50. Затраты складываются по пройденным
уровням. Это упрощённая модель различий между уровнями памяти,
а не измерение задержек конкретного процессора.

В двух программных моделях стоимость поиска в кеше не учитывается.
Поэтому их результаты характеризуют число необходимых загрузок,
а не время выполнения запросов. Результаты разных моделей не образуют
единого рейтинга.

## Основные результаты

- **Вместимость меняет выбор алгоритма.** При смене часто используемого набора
  лучшим оказался LIRS для 32 объектов, LRU для 64 и LFU для 290.
  При том же размере другая последовательность запросов может дать другого победителя.
- **Польза сочетания алгоритмов зависит от нагрузки.** В процессорной модели
  при размерах 2+32+256 и смене часто используемого набора разные алгоритмы
  на уровнях дают среднюю стоимость 11,058 против 11,564 у лучшего варианта
  с одинаковым алгоритмом на всех уровнях. Для некоторых других запросов
  выигрыш мал или отсутствует.
- **Разделение памяти иногда уменьшает число загрузок.** При одинаковом по стоимости доступе
  ко всем уровням и общем объёме 290 объектов сочетание LRU(56) → LIRS(234)
  даёт 952 загрузки против 1356 у лучшего одного уровня за 6000 запросов
  в примере переходов между страницами.
- **Третий уровень не улучшил минимум в исследованных случаях свободной модели.**
  Во всех 58 исследованных сочетаниях вида запросов и общего объёма достаточно
  одного или двух уровней. Это вывод для пяти выбранных алгоритмов и
  рассматриваемых последовательностей, а не для любых систем кеширования.

## Условия и границы исследования

Все объекты имеют одинаковый размер. Кеши в начале каждой последовательности
пусты; первые загрузки входят в результат. При сравнении конфигураций
используются одинаковые запросы.

Одноуровневый кеш и процессорная модель исследуются на последовательностях
из 20 000 запросов при пяти начальных значениях генератора. В свободной
многоуровневой модели конфигурации подбираются на одной последовательности
из 6000 запросов, затем сравниваются на двух дополнительных последовательностях
без повторного подбора. Для детерминированных запросов смена начального значения
не меняет последовательность и не является независимой проверкой.

В свободной модели представлены 58 из 60 сочетаний вида запросов и объёма.
Для равномерных случайных запросов и неравномерной популярности при объёме
290 результатов нет. Точный минимум установлен только для представленных
сочетаний, среди допустимых разбиений на 1–3 уровня и пяти алгоритмов.

[Методика исследования](methodology.md) содержит определения алгоритмов,
описания последовательностей запросов, формулы метрик и объяснение
сравнения с идеальным алгоритмом REF.
