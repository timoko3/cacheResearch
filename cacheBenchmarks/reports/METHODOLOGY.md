# Методика исследования кеширования

[Основной README](../../README.md)

## Термины и общие условия

**Страница** — единица данных с уникальным идентификатором.
Все страницы имеют одинаковый
размер.

**Вместимость** — максимальное число страниц, одновременно хранимых в кеше.
Служебные структуры алгоритма и история идентификаторов вытесненных страниц
в эту вместимость не входят. Поэтому одинаковая вместимость не означает
одинакового полного расхода памяти реализациями.

**Попадание на уровне** означает, что страница найден в этом кеше.
**Промах на уровне** означает, что страница передаётся на поиск следующему уровню.
**Загрузка из источника** нужна только при отсутствии страницы на всех уровнях.
Для одноуровневого кеша каждый промах приводит к такой загрузке.

**Многоуровневая система** задаёт число уровней, вместимость и алгоритм каждого уровня.
Запись LRU(56) → LIRS(234) обозначает два уровня общей вместимостью 290 страниц.

Все кеши начинают обработку последовательности пустыми. Первые загрузки входят
в результат; отдельный период предварительного заполнения не выделяется.
В пределах одного эксперимента системы сравниваются на одинаковых запросах.

**Начальное значение генератора** определяет воспроизводимую случайную
последовательность при фиксированных параметрах генерации.

### Алгоритмы вытеснения

Алгоритм вытеснения выбирает страницу для удаления, когда кеш заполнен.

| Алгоритм | Основная идея |
|---|---|
| LRU | Удалять страницу, к которому дольше всего не обращались |
| LFU | Удалять страницу с наименьшим счётчиком обращений с момента его загрузки |
| ARC | Адаптивно распределять память между недавно и повторно использованными страницами |
| 2Q | Отделять недавно загруженные страницы от страниц с подтверждённым повторным использованием |
| LIRS | Оценивать повторное использование страниц с учётом интервалов между обращениями и истории запросов |

## Последовательности запросов

В таблице приведены параметры последовательностей, использованных в отчётах.
Часто запрашиваемый набор страниц называется **горячим множеством**.

| Вид запросов | Идентификатор в данных | Построение последовательности |
|---|---|---|
| Цикл 145 страниц | small_cycle | Повторяющийся обход 145 страниц в одном порядке |
| Цикл 291 страницы | boundary_cycle | Повторяющийся обход 291 страницы в одном порядке |
| Последовательный проход | scan | Повторяющийся обход 1160 страниц |
| Постоянное горячее множество | hot_cold | С вероятностью 90% выбирается один из 36 горячих страниц, иначе — страница из отдельного набора из 1160 страниц |
| Горячие страницы и сканирование | hot_scan | 384 случайных обращения к горячему множеству из 36 страниц чередуются со 128 обращениями к новым страницам |
| Смена горячего множества | phase_change | Правило 90%/10% сохраняется, но горячее множество меняется каждые 2000 запросов между четырьмя непересекающимися наборами по 36 страниц |
| Серии повторных запросов | bursts | Случайно выбранный из 1160 страниц повторяется 16 раз подряд |
| Равномерные случайные запросы | uniform | Каждый из 1160 страниц выбирается с одинаковой вероятностью |
| Неравномерная популярность | popular | Для 1160 страниц вероятность выбора страницы с номером k пропорциональна 1/(k+1), начиная с k = 0 |
| Переходы между страницами | navigation | Детерминированная последовательность обращений к общим и отдельным ресурсам страниц |
