# Кодстайл C++

Правила действуют для библиотеки, приложения, бенчмарков и тестов этого
репозитория. Основа — существующий стиль проекта: PascalCase для типов,
camelCase для функций и переменных, завершающий `_` для скрытых полей.
Сторонние зависимости и сабмодули используют собственный кодстайл.

## Имена

Эти правила проверяет `readability-identifier-naming` в корневом `.clang-tidy`.
Нарушение считается ошибкой и останавливает проверку CI.

| Категория | Правило | Примеры |
|---|---|---|
| Пространства имён, включая inline | snake_case | `cache`, `parser`, `cache_tools` |
| Классы, абстрактные классы, структуры, union | PascalCase | `CacheLRU`, `CacheDescription`, `PageRecord` |
| Типы перечислений | PascalCase | `CacheLevel`, `CacheEviction`, `ResidentQueue` |
| Значения перечислений, включая enum class | UPPER_CASE | `L1`, `C_LRU`, `A1_IN`, `REFRESH_LIR` |
| Псевдонимы `using` и `typedef` | PascalCase без `_t` | `Base`, `PageResult`, `PageIterator` |
| Функции и методы, включая static, virtual и constexpr | camelCase | `lookupUpdate`, `getPage`, `makeCache` |
| Локальные и глобальные переменные, указатели, ссылки | camelCase | `loadedPage`, `residentToEvict`, `pageIndex` |
| Параметры функций, лямбд и пакеты параметров | camelCase | `requestedKey`, `slowGetPage`, `args` |
| Публичные поля экземпляра | camelCase | `amountRequests`, `repetitionCount` |
| Private/protected поля экземпляра, включая const | camelCase + `_` | `pageIndex_`, `configParsed_`, `ghostLimit_` |
| Статические поля и константы класса | camelCase | `failingValue`, `failCopy` |
| Глобальные, локальные и static константы, constexpr переменные | camelCase | `maxCacheLevel`, `policyNames`, `initialFrequency` |
| Типовые и шаблонные параметры шаблонов | PascalCase | `T`, `F`, `KeyT`, `CacheT`, `Strategy` |
| Нетиповые параметры шаблонов | camelCase | `capacity`, `maxLevels` |
| Макросы, включая include guards | UPPER_CASE | `CACHE_SYSTEM_H`, `CACHE_TESTS_TOOLS_H` |

`const` у локальной переменной или параметра не меняет стиль имени. Префиксы
типов вроде `m_`, `p_`, `str_` не требуются; Hungarian notation не включена.
Имена типов больше не получают суффикс `_t`. Аббревиатуры алгоритмов сохраняются:
`CacheLRU`, `CacheLFU`, `CacheARC`, `CacheLIRS`, `CacheREF`, `Cache2Q`.
Однобуквенные `i`, `j`, `T`, `F` допустимы для коротких локальных областей и
параметров шаблонов. Содержательность имени и уместность сокращения проверяет
ревью: clang-tidy проверяет форму, а не смысл.

```cpp
namespace cache {

enum class PageStatus { RESIDENT, GHOST };

struct CacheDescription {
    std::size_t size;
};

template <typename T, typename KeyT = int>
class Cache {
private:
    using PageIndex = std::unordered_map<KeyT, T>;
    PageIndex pageIndex_;
    const std::size_t capacity_;

public:
    explicit Cache(std::size_t capacity) : capacity_(capacity) {}
    std::size_t getCapacity() const noexcept { return capacity_; }
};

} // namespace cache
```

## Исключения и внешние контракты

Не переименовываем имена, заданные внешним API: например, специализацию
`std::hash`, переопределение `SetUp()` из GoogleTest и стандартный `main`.
Clang-tidy учитывает специализации, переопределения и определения из макросов;
имена, сгенерированные GoogleTest, не задают стиль обычного кода проекта.
Для новых собственных имён нет регулярных выражений, исключающих их из проверки.

Если диагностике требуется исключение, используем локальный
`NOLINTNEXTLINE(точное-имя-проверки)` с комментарием о причине. Не отключаем
проверку для файла целиком и не добавляем исключения для удобства именования.
Существующий тест неизвестного значения enum содержит такое исключение для
анализатора, поскольку намеренно проверяет обработку недопустимой стратегии.

## Обновлённые публичные имена

Прежние имена переименованы вместе со всеми обращениями в проекте; совместимые
псевдонимы со старым написанием не добавляются.

| Прежнее имя | Новое имя |
|---|---|
| `cache::cacheDescription` | `cache::CacheDescription` |
| `cache::cacheStats` | `cache::CacheStats` |
| `cache::cacheSystemParams` | `cache::CacheSystemParams` |
| `cache::cacheLevel_t` | `cache::CacheLevel` |
| `cache::cacheEviction_t` | `cache::CacheEviction` |
| `Cache<T, KeyT>::pageResult_t` (protected) | `Cache<T, KeyT>::PageResult` |

Внешним потребителям и собственным наследникам `Cache` нужно обновить эти имена.
Имена классов кешей, методов, значения `L1`–`L5` и `C_LRU`/`C_LFU`/прочие
значения стратегий сохраняются.

## Форматирование

Точные настройки находятся в корневом `.clang-format`; он явно фиксирует
настройки clang-format 18.1.3. Подкаталоги наследуют этот файл.

- C++17; четыре пробела, табуляция запрещена. Продолжения строк тоже имеют отступ
  четыре пробела. Окончания строк LF закреплены в `.gitattributes`.
- Целевая длина строки — 100 символов. clang-format может оставить более длинную
  строку, если её нельзя разбить по своим правилам.
- Открывающая фигурная скобка находится на строке объявления или условия.
- Содержимое namespace не получает дополнительного отступа; закрытие namespace
  сопровождается комментарием, который поддерживает clang-format.
- Метки `case` и `default` имеют отступ относительно `switch`.
- Указатели и ссылки примыкают к типу: `T* ptr`, `const T& page`.
- Перед скобкой управляющей конструкции есть пробел: `if (ready)`, `for (...)`.
  У вызова функции пробела нет: `getPage(key)`.
- Короткие функции, определённые внутри класса, могут быть однострочными;
  короткие лямбды тоже. `if`, циклы и обычные блоки не сжимаются в одну строку.
- Include сортируются с учётом регистра и группируются: системные заголовки,
  GoogleTest/GoogleMock, затем заголовки в кавычках. Собственный основной заголовок
  файла может стоять первым по правилам clang-format.

Имена файлов не проверяются clang-format или этой проверкой clang-tidy.
Существующая структура путей сохраняется: `cache/cacheLRU.h`,
`tests/LRU_tests.cpp`, `tests/cache_headers/LRU.cpp`. Изменение путей требует
отдельного обновления include, CMake и документации.

## Проверки

Запуск остаётся прежним, из корня репозитория:

```sh
python3 scripts/code_quality.py format
python3 scripts/code_quality.py format-fix
cmake --preset debug
python3 scripts/code_quality.py tidy --build-dir build/debug
```

Чтобы автоматически исправить именование и форматирование:

```sh
python3 -m pip install PyYAML
cmake --preset debug
python3 scripts/code_quality.py style-fix
```

PyYAML нужен только для `style-fix`. Команда сначала собирает исправления
`readability-identifier-naming` из всех единиц трансляции, затем применяет их
вместе к отслеживаемым файлам проекта. Общие заголовки и обращения к их именам
переименовываются за один проход применения, без промежуточной поломки анализа.
Повторяющиеся исправления объединяются; конфликтующие исправления или изменение
файла во время анализа останавливают применение. Зависимости не редактируются.
После переименования выполняются форматирование и повторная проверка имён.
Диагностики, для которых clang-tidy не предложил исправление, остаются ошибками.
Ссылки в документации, Python и других языках автоматически не переименовываются;
их нужно обновлять вместе с изменением публичного API.

На Windows используйте `python` вместо `python3`. Скрипту нужны
`clang-format-18` и `clang-tidy-18` из LLVM 18 в PATH. Patch-версия форматтера
может отличаться; конкретные версии Nix-окружения закреплены в `flake.lock`.
`format` и `tidy` проверяют без исправлений, `format-fix` меняет форматирование.
Автоматическое переименование выполняется только явной командой `style-fix`.

Скрипт проверяет отслеживаемые Git C/C++ файлы. Новые файлы нужно добавить в Git.
Заголовки анализируются через включающие их единицы трансляции; отдельные
проверки заголовков в `tests/cache_headers` обеспечивают их самостоятельную
компилируемость. Диагностики зависимостей фильтруются, но ошибки компиляции
в зависимостях остаются ошибками.

Наряду с именованием включены Clang Static Analyzer и выбранные проверки
`bugprone`. Полный список хранится в `.clang-tidy`. Кодстайл не задаёт новую
политику исключений, владения или алгоритмов кеширования: эти контракты
проверяются отдельно от формы записи и имён.
